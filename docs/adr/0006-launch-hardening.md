# 0006: Launch hardening choices (site config, service worker, Lighthouse, preview fidelity)

- Status: accepted
- Date: 2026-11-25

## Decisions

1. **One site config.** `apps/web/site.config.ts` holds the name, tagline, production URL,
   repository, contact addresses and analytics choice, with `SITE_*` build-time overrides.
   Everything else reads from it: page titles, SEO tags, sitemap, robots, manifest, OG images,
   privacy page, CSP. `pnpm check:launch` (run by the release workflow) fails while placeholders
   remain.
2. **Analytics off by default.** The only supported provider is Cloudflare Web Analytics
   (cookieless). Its two hosts enter the CSP only when a token is configured, and the token
   never reaches the JS bundle (only the provider name does).
3. **Hand-written service worker** (`apps/web/build/sw-template.js`, ~80 lines) instead of
   Workbox / vite-plugin-pwa (dozens of transitive packages). It precaches the app shell and
   caches WASM, pdf.js and OCR data on first use. It never calls `skipWaiting` by itself: the page
   asks, through a button that is disabled while any operation runs, so code is never swapped
   mid-operation. Cached responses keep their CSP headers. Matching ignores `Vary` because static
   hosts send `Vary: Origin` and module scripts are requested with an Origin.
4. **Lighthouse is run with `npx`, not installed.** `lighthouse` 13 depends on a telemetry
   package under the Functional Source License, which is outside our licence allowlist
   (STANDARDS §9). It is a CI-only measuring tool that never ships. It runs with install scripts
   disabled, pinned to an exact version, and in a job that does not share the dependency cache.
5. **Preview matches the static host.** Vite runs in `mpa` mode. The preview server resolves
   clean URLs (`/merge` → `merge/index.html`) and serves `404.html` with a 404, the way
   Cloudflare Pages and the nginx image do. A preview SPA fallback had hidden a wrong service
   worker precache and per-route metadata.
6. **Committed raster assets.** Icons, OG images and the landing screenshot are generated by
   `pnpm images` (Playwright) and committed, so builds and the Docker image need no browser.
   They must be regenerated after a rename (`docs/LAUNCH.md`).

## Consequences

Renaming or re-domaining the product is one file plus `pnpm images`. The offline behaviour,
update flow and SEO output are all covered by e2e tests against the production build.
